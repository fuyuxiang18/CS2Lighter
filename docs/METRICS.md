# 个人统计口径

适用版本：CS2Lighter 0.3。统计来源是本地已解析的 CS2 demo；同一 checksum 只计算一次，仅按用户绑定的 SteamID 纳入个人数据。昵称只用于寻找身份，不用于合并账号。职业参考 demo 不会因为名字相似而进入个人统计。

## 市场参考与产品取舍

- **HLTV**：目前的 Rating 3.0 包含经济修正、Round Swing，以及击杀、伤害、生存、KAST 和多杀等子评分，需要地图、经济和职业赛事样本的基准模型。2.0 官方明确不公开完整公式。本应用不把社区回归公式或解析器的 `hltv_rating_2` 字段称为官方评分。[Rating 3.0](https://www.hltv.org/news/42485/introducing-rating-30)、[2.0 的公开范围](https://www.hltv.org/news/20695/introducing-rating-20)。
- **FACEIT / ESEA**：公开的 RWS 按胜方伤害分配回合份额，并给予成功爆炸的下包者或拆包者目标得分。FACEIT Rating / Round Swing 是另一套考虑胜率变化和局势的模型，不能把 RWS 当成它。[RWS 官方说明](https://support.faceit.com/hc/en-us/articles/19309126922140-FACEIT-CS2-Advanced-Stats)、[FACEIT Rating](https://support.faceit.com/hc/en-us/articles/26530513602716-FACEIT-Season-8-FACEIT-Rating-FAQ)。
- **Leetify**：强调经济与胜率背景下的贡献，并展示瞄准、道具、残局、地图、补枪和开局对枪。官方也提醒，表现分受对手强度影响，不适合直接比较普通玩家与职业选手。[Leetify 评分说明](https://leetify.com/blog/introducing-leetify-rating/)。
- **Scope.gg**：常见项目包括 ADR、KAST、KPR、K/D、爆头、首发命中、击杀用时、投掷物伤害/致盲、地图阵营拆分和近期趋势，并提供 2D 回放。本版本优先实现事件数据能验证的部分。[产品说明](https://scope.gg/)。
- **CSStats**：提供完整比赛历史、开局、补枪、残局、逐回合击杀过程和个人趋势。本应用对应保留逐场记录与原回合回放入口。[产品说明](https://csstats.gg/)。

## 样本与时间范围

1. 只取编号大于 0、结束 tick 晚于开始 tick、获胜阵营为 T/CT 的已结束回合。热身和未结束尾回合不进入分母。
2. `player_economies` 的玩家回合记录确认参赛和阵营；没有记录时不假造一个零表现回合。页面显示可用比赛数、纳入比赛数和跳过数；逐场记录同时保留 demo 总回合数与个人参赛回合数。只有没有任何有效个人回合的比赛才算覆盖缺失；选择 CT 时某场仅打过 T，不会被误报为数据不完整。
3. 普通击杀、死亡、伤害与投掷统计覆盖回合开始至正式回合结束（包含结束后的存枪/追枪时段）。开局击杀、残局和 RWS 限定到胜负已确定的 `end_tick`；结束后的追枪伤害不增加 RWS。
4. 可按地图、阵营、来源筛选。返回的数据同时列出地图、游戏 build、模式和来源分组；总览是所选样本的描述，不是控制了这些因素的能力排名。
5. 只统计 demo 中观测到的内容。掉线、替补、缺失记录和不同解析版本会影响覆盖；未知结果不是平局。平局需要最终等分、没有胜者且达到配置的比赛回合上限。

## 基础指标

| 指标            | 计算规则                                                                                            |
| --------------- | --------------------------------------------------------------------------------------------------- |
| 比赛胜率        | 胜场 ÷ 已知结果的胜/负/平场次；平局算分母、不算胜场；未知结果排除                                   |
| 回合胜率        | 获胜个人参赛回合 ÷ 个人参赛回合                                                                     |
| K / A / D       | 对敌方的击杀 / demo 记录的对敌击杀助攻 / 全部死亡；自杀、世界与队友击杀导致的死亡仍计 D，但不奖励 K |
| K/D、KDA        | 总 K ÷ 总 D；(总 K + 总 A) ÷ 总 D                                                                   |
| 爆头率 HS%      | 爆头击杀 ÷ 全部敌方击杀；是击杀爆头率，不是命中头部的子弹比例                                       |
| ADR / KPR / DPR | 总有效敌方生命伤害 / 总 K / 总 D，分别除以个人参赛回合数                                            |
| KAST            | 至少发生击杀、助攻、生存或被补枪其中一项的回合数 ÷ 参赛回合数；同一回合只计一次                     |
| 生存率          | 没有个人死亡事件的参赛回合 ÷ 参赛回合                                                               |

生命伤害按 `min(health_damage, victim_health)` 计，排除过量伤害、自伤与队友伤害；队友伤害单列。控制机器人产生的事件不冒领到控制者。所有比例先合计分子、分母，再做除法，不平均各场百分比。分母为零显示缺失值，不显示无穷、NaN 或假零。

## Rating：公开历史 1.0

字段：`hltvRating1`；方法 ID：`hltv-1.0-public`。

设 R 是符合条件的参赛回合，K 是总敌方击杀，S 是存活回合，M 是逐回合击杀数平方之和：

```text
Rating 1.0 = [ K/R/0.679 + 0.7 × S/R/0.317 + M/R/1.277 ] / 2.7
M = Σ(该回合击杀数²)
```

资格有两条路径，逐场记录在 `ratingEligibilityBasis` 中：

- `mode`：Premier、Competitive、5v5 Scrimmage 的明确模式元数据。
- `observed-5v5`：第三方服可能把标准比赛记录为 Casual。至少五个已结束回合、至少一个完整 5v5 回合、所有已观测回合每阵营不超过五人，且最大回合设置为 24/30 或最终一队至少 13 分，可按观测到的比赛结构使用历史公式。原始模式和来源照常保留，不改写成官方竞技模式。

两条路径都排除同人单回合多次死亡、超过五杀或超员的比赛；Wingman、死亡竞赛、军备、合作等明确不兼容模式也排除。这是本地结构性判断，不能证明服务器所有规则与官方赛事完全相同。`ratingRoundCount` 给出实际参与评分的回合数。

这个历史公式的平均值来自旧时代 CS 数据，没有现代 CS2 的经济、地图、阵营与对手强度修正；1.00 不是对当前用户群重新校准的平均水平。它既不是官方 HLTV 2.0/2.1/3.0，也不是完美平台 Rating。[原始公开说明与公式入口](https://www.hltv.org/news/4094/what-is-that-rating-thing-in-stats)。

## RWS：FACEIT 2025 公开规则的本地复算

方法 ID：`faceit-2025-public-local-v1`。它是本地统计，不代表 FACEIT/ESEA 服务器给出的认证分数，也不冒充完美平台未公开的 RWS 口径。

```text
输掉回合：0
普通获胜回合：100 × 个人敌方生命伤害 / 胜方全队敌方生命伤害
爆炸/拆包获胜：70 × 上述伤害份额 + 30 × 是否完成获胜目标
总 RWS：各有效个人参赛回合 RWS 之和 / 有效回合数（包含败局的 0）
```

只有下包后炸弹成功爆炸才给下包者 30 分；下包后靠歼灭获胜不给目标加分。拆包回合给拆包者 30 分。所有队友（包括机器人）的伤害进入全队分母；控制机器人的伤害和目标奖励不归控制者。双方伤害都截断在该回合胜负确定时，炸弹世界伤害不作为玩家伤害。

官方说明没有定义全队零伤害时如何分配剩余份额。本实现将此类胜局，以及目标事件缺失的胜局，设为 `null` 并排除 RWS 分母；败局仍为 0。页面必须一起展示 `rwsRoundCount` 和 `rwsMissingRoundCount`，缺失较多时不宜比较分数。官方例子可直接验证：140/500 伤害为 28；再输一局后均值 14；拆包者 100/300 伤害为 53.33。[公开公式和例子](https://support.faceit.com/hc/en-us/articles/19309126922140-FACEIT-CS2-Advanced-Stats)。

## 开局、补枪、残局与多杀

- 开局对枪是每回合胜负确定前的第一笔敌方击杀；同 tick 按 frame 和事件 ID 稳定排序。它不等于“第一个进入包点的人”。尝试率 = (首杀+首死)/参赛回合；成功率 = 首杀/(首杀+首死)；首杀转化率 = 首杀后赢下的回合/首杀回合。
- 补枪使用本地固定 **5 秒**窗口：队友被某敌人击杀后，同回合杀死该敌人计一次补枪。一次补枪可替多名队友报仇，但补枪者该次击杀只计一次；每名队友的该回合被补死亡最多记一次。与平台不同的窗口或因果模型不保证一致。
- 残局复用解析器记录的 1vX 事件，每玩家每回合只保留首次进入的 X；统计尝试、成功与成功率，并按对手数分组。保枪失败也在解析器记录的尝试分母中，不据此直接评价决策好坏。
- 多杀是每回合恰好 0/1/2/3/4/5 杀的分布；非标准模式超过五杀合入展示的 5+ 档，不能参与 Rating 1.0。

## 道具、经济、武器与趋势

- 道具伤害统计 HE、燃烧瓶和燃烧弹的敌方生命伤害；各类投掷次数来自 `shots` 中的实际使用事件，烟雾数量不表示烟的质量。
- “致盲敌人”是致盲持续 **超过 1 秒的事件数**，不是整场去重人数；敌方致盲秒数合计所有正时长事件，多次重叠致盲未做连续时间合并。队友致盲也按超过 1 秒单列。每闪致盲 = 敌方致盲事件数/闪光投掷数；闪光助攻来自击杀事件标记。
- 经济统计个人回合开始装备价值与花费，沿用解析器的 pistol/eco/semi/force-buy/full 分类。平均值只使用这两个数值都存在的回合，显示 `economyRoundCount`。分类描述投入，不能直接评价“该不该买”。
- 武器表提供击杀、爆头击杀、伤害、开火事件数量。伤害事件/子弹数不能可靠表示命中率：穿透、多目标和霰弹会破坏一一对应关系。因此本版不输出伪命中率、首发命中率或反应速度。
- 地图和阵营表展示样本数，逐场趋势保留日期、checksum、首个有效回合/tick，支持回到原始回放。图表变化可能来自地图、模式、角色、队友或对手强度变化，不能仅凭相关性下因果结论。

## 缓存与复现

每次解析/升级缓存版本后，`computePersonalMatchStats` 从事件表生成全场所有玩家的紧凑回合事实，写入同一份 per-demo 缓存。个人统计只读取缓存并聚合，不在每次打开面板时重扫位置或伤害表。缓存版本、解析日期及比赛/地图元数据变化会触发重建。

实现与测试：`src/node/database/personal-stats/`。公式、分母、过滤、过量伤害、RWS 目标分、机器人控制、补枪窗口、缺失回合和跨场加权均有确定性用例。

## v0.4：个人风格与复盘候选

风格只描述实际样本比例，不是与虚构玩家群比较的能力分。跨场先合计分子和分母：

| 维度             | 分子 / 分母                                       |
| ---------------- | ------------------------------------------------- |
| 首对枪参与       | 本人取得首杀或首死的回合 / 参赛回合               |
| 补枪击杀占比     | 5 秒窗口内的补枪击杀 / 敌方击杀                   |
| 道具使用回合占比 | 至少使用一个闪、烟、雷、火或诱饵的回合 / 参赛回合 |
| 生存             | 存活回合 / 参赛回合                               |
| 残局遭遇         | 解析器记录本人进入 1vX 的回合 / 参赛回合          |

少于三场或对应分母少于 30 时标记样本有限；超过此门槛也不代表统计显著，更不代表高比例一定更好。

复盘卡每个回合最多计一次。界面优先显示涉及比赛更多、出现次数更多的场景，方便寻找重复行为；这不是失误严重度排名：

| 候选       | 触发回合 / 机会分母                                | 证据事件                          |
| ---------- | -------------------------------------------------- | --------------------------------- |
| 首死       | 本人首死 / 本人首杀或首死                          | 首死 tick                         |
| 首杀后未赢 | 本人首杀但回合失败 / 本人首杀                      | 首杀 tick                         |
| 死亡未被补 | 死亡数大于被补死亡数 / 发生死亡的回合              | 单次死亡时使用死亡 tick           |
| 队友致盲   | 致盲队友超过 1 秒 / 投掷闪光或已记录队友致盲的回合 | 本回合首次符合条件的队友致盲 tick |
| 残局未赢   | 进入 1vX 但未赢 / 进入 1vX                         | 首次进入残局 tick                 |

“死亡未被补”包含自杀、世界和友伤死亡；非标准复活模式单回合多次死亡时仅跳回合开头，避免把首次死亡误标为未被补的那次。“首死”不是按秒定义的早死。“未被补”不表示当时具备补枪机会，也不表示队友失误。首杀后丢局和残局失败不能直接归因于本人决策；队友致盲仍需结合位置与沟通复核。本版不推断持道具死亡、准星质量、反应时间或可见性。

每张卡保留完整触发数和机会分母，并提供最多六个最新比赛的回合证据；`evidenceTotal` 为可回放证据总数，不受六条展示上限影响。少于三场或机会分母少于 10 标记样本有限。不存在机会时不生成 0% 结论；没有触发的主题不生成问题卡。

缓存 schema 3 从已有数据库事件表补充首杀、首死、死亡、队友致盲和残局 tick，以及比赛 tickrate；不重新解析原 demo。有有效事件时间及 tickrate 时，从事件前最多八秒开始播放，通常不早于冻结结束；异常冻结期事件不把起点放到事件之后。返回 `eventTick` 和 `precision=event-context`。缺失事件时间或时钟时明确降级为 `round-start`。精确事件是回放线索，不是自动判错。

## v0.4：同条件变化与训练跟踪

自比较严格按“地图名、阵营、来源、原始模式、游戏 build”组成分组，不跨组拼接。游戏 build 是现有缓存可用的版本代理，并不保证社区地图文件完全相同。同组最近最多十场按比赛日期排序，分成较早和近期两个互不重叠的完整比赛窗口，每期最多五场；每期至少两场、20 个该阵营参赛回合才显示可比较状态。

每项指标还要求两期各自满足机会数：ADR、首对枪参与、道具使用和生存至少 20 回合，爆头率至少 10 杀，被补死亡占比至少 10 次死亡，首杀转化至少五次首杀。未达门槛仍显示原始样本，但变化量为缺失；百分比变化用百分点，ADR 用每回合伤害差。门槛是展示保护，不是显著性检验。即便同组也没有匹配对手强度、角色、出生位、经济或队友，因此不输出因果判断或统一“进步分”。

训练计划保存一个固定 `ReviewTrainingScope`：主题、开始时间、地图、阵营、来源、模式、build。它独立于页面当前筛选。基线采用实际比赛日期 `<= startedAt` 的最近最多五场，练习后采用 `> startedAt` 的最近最多五场；导入旧 demo 不会把比赛变成练习后样本。两期使用所选卡完全相同的触发与分母口径，各至少两场、20 回合且机会分母至少五，才标记可比较。零机会返回 `null`，有机会但零触发返回 0%；不因比例下降自动宣称训练有效。

统计与复盘共享同一份 per-demo 缓存。全命中读取不进入全局导入进度；真正缺失或失效时才报告重建。实现与确定性测试：`src/node/database/review/`。
