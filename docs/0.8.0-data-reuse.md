# v0.8.0 数据复用与复盘

## 范围

基于开源 demo 项目的源码调研，优先落地：同场窗口合并读取、紧凑位置块、独立计算版本、统计到交火复盘的短路径、录制与编码衔接。保留现有 Go 解析器与 Electron/PostgreSQL 架构，不额外引入 Python/.NET 运行时。

## 兼容性

- 数据库 schema 16 仅新增 `player_position_blocks`。旧 `player_positions` 保留，查询支持两种格式；没有后台全库改写。
- 位置块按玩家/回合组织，最多 2048 行，保存原始 CSV 行序号、Float64 数值、布尔位和字符串字典；Deflate 压缩并校验 SHA-256。损坏块报错，不静默返回不完整证据。
- 新导入直接写位置块。回放、习惯聚合和死亡快照通过统一读取层加载。完整回放保持现有缺帧填充；诊断与短片预览只读取真实记录。
- schema-3 的逐 demo 摘要继续可用。缺失 `calculations` 的旧文件按 habits=1、metrics=1 处理；格式版本与两类计算版本分离。更改统计公式不必重新算热力图，也不读取原 demo。
- 死亡证据继续使用原有逐次缓存格式。规则和环境校验保持不变，批量本身不使旧缓存失效。

## 批量死亡取证

同 demo、同数据修订的等待任务短暂合并，按最多 4096 个唯一 tick 的预算分组。开局短前缀保留逐窗口直接读取；预计能省下足够重复前缀扫描时，一次原生扫描输出多个窗口。完整校验成功后逐窗口评估与保存，保留每个窗口独立的未知实体类覆盖，防止后续回合的信息污染较早窗口的证据资格。

输出有大小上限，小批次使用受限内存缓冲，大批次在本次任务目录保存压缩差分，成功、失败和取消均清理。密集场景触及共享输出预算时拆成较小批次重试，保留原有校验和字段。单窗口仍走直接路径。取消一个死亡不会取消同批其余死亡；全部取消会中止原生进程。损坏/截断输出不计作完成。

界面保存最多 32 个任务键和进度摘要；重新进入时从服务端读取现状，不自动重启已暂停的工作。启动批量可复用已完成结果。批次超预算或请求错开合并时机可能分多次扫描，不承诺一个 demo 永远只读取一次。

## 即时复盘与录像

短片预览读取同一回合、最多 45 秒的保存位置，使用实际 tickrate，显示最近且不超过 0.2 秒的真实帧，不借用未来位置，不跨长缺口补点。位置和朝向用于理解战况，不作为无遮挡枪线证明。

真实录像保留同一个兼容游戏环境内跨 demo 共用进程的机制。采集顺序与成片顺序分离；前向跳转避开无用的 tick 0 循环，重叠/后退保留安全重置。单路编码与采集衔接，最多两段积压；结束、取消和失败先等待编码退出再清理。不同历史版本的游戏环境不强行合并。

## 验证与后续

真实 demo 通过完整 CSV 编解码逐字段对照，并在独立 PostgreSQL 中验证新入库、旧格式查询、热力图汇总、死亡记录及摘要热读取。`scripts/benchmark-death-evidence.mjs` 支持指定本地 demo 和窗口，比较单窗/合并扫描的状态、射击与覆盖结果；不保存玩家身份或原始 demo。

后半场三个窗口共 1347 帧、33 次射击通过完整对照，扫描次数从 3 次降至 1 次。验证发现并修复了动态数组字段消失后仍残留在后续窗口的问题。性能测试区分原生读取、窗口整理和验证哈希耗时；共享 CPU 的样本不作为普遍速度承诺。

独立安装环境验证 0.7.4 → 0.8.0 覆盖安装和卸载的数据保留；桌面实测 18 条死亡分析保存、即时地图播放、960×720 窗口以及中英文切换。录像编排通过调度、取消、失败与编码回归测试，本次未启动 CS2 测量实际录制耗时。

后续优先事项：提供可暂停的旧位置数据压缩；在真实 demo 上验证可恢复 FullPacket 索引；验证新版解析器 UserCmd 基线恢复；历史资源档案需要原始 VPK 身份与材质证据后才参与精确枪线判断。R4 不因换库或粗略地图数据而重新开放。
