# CS2Lighter 0.4 产品取舍

本文件记录 0.4 的产品方向与验收原则，不代表所有构想均已发布。调研日期：2026-10-04。竞品信息来自官方公开页面，未登录付费产品实测，不将宣传效果当作独立验证的事实。

## 用户为什么还需要安装一个工具

目标用户已经能在对战平台看战绩。CS2Lighter 应帮助他们从自己导入的比赛里找到值得复核的重复场景，选定一个下一场能执行的动作，再回来核对变化。

产品的价值假设是：完美平台等用户愿意为了本地文件夹自动导入、demo 无需上传、少量有证据的复盘问题和持续的个人记录，承担安装与本地解析成本。这仍需通过实际使用验证。不能把“多统计几项”或“用了 AI”视为价值已经成立。

首屏应能回答三件事：现在值得看什么；证据在哪个回合；下一次准备尝试什么。样本不足时，显示实际例子和限制，不制造一个必须改掉的坏习惯。

## 现有产品已经提供什么

| 官方来源                                            | 公开展示的能力                                                                   | 对本产品的约束                                                           |
| --------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| [完美世界竞技平台](https://pvp.wanmei.com/?cupId=0) | 战绩与 DEMO、自动精彩片段、道具教学与练习                                        | 不能仅靠重新展示赛后数据吸引下载；公开网页不足以证明平台缺少某项深入分析 |
| [Leetify](https://leetify.com/)                     | 自动比赛报告、个人记录、评分、好友比较                                           | 总分与个人最佳都不是独有功能                                             |
| [SCOPE.GG](https://scope.gg/)                       | 失误分析、位置建议、趋势、道具和瞄准数据；FAQ 描述最近 30 场、前后各 15 场的比较 | “失误卡片”“热力图”“与过去相比”单独也不构成差异化                         |
| [SCOPE.GG 回放](https://scope.gg/replay/)           | 不启动游戏的 2D 回放、回合与事件定位                                             | 回放是必要基础能力，需要和待复核的问题直接相连                           |

我们选择验证的是整段使用过程：本地导入 → 找到重复场景 → 查看上下文 → 用户确认意义 → 选择一个动作 → 在之后的同类场景中复核。不能宣称其他产品没有这一过程；本地适配、解释质量和使用成本是否更合适，要靠目标用户判断。

## 必要、辅助与移出主流程

| 层级       | 内容                                                                 | 取舍理由                                       |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------- |
| 必要       | 用户指定文件夹、进度与失败重试、精确昵称识别后绑定账号               | 保证本地数据持续进入，也让用户知道缺失来自哪里 |
| 必要       | 少量待复核场景、明确规则、分子与分母、数据覆盖、可回看的具体回合     | 每条观察都能核实；不把统计关联包装成教练判断   |
| 必要       | 复核状态、可取消的编辑、一个当前行动、个人前后比较                   | 让一次复盘能延续到下一次，而不是看完数字就离开 |
| 辅助       | 热力图、路线、阵营、装备、人数局面、完整比赛库                       | 为当前问题补充背景，按需展开                   |
| 辅助       | KDA、ADR、KAST、Rating 等基础数据                                    | 仍可查阅和导出，但不占据首屏的主要空间         |
| 移出主流程 | 大量总分卡、无文字的工具图标、默认全历史、与当前问题无关的长事件表   | 降低进入复盘前的理解和操作成本                 |
| 暂不推断   | 人格式角色标签、段位百分位、自动“正确决策”、未经验证的瞄准或反应评分 | 现有数据与验证不足以支持这些结论               |

许可证和关于页鸣谢保留；旧资料库、绑定身份、已有本地记录和缓存的兼容性不因界面重做而破坏。已移除的封禁、下载、置顶玩家和高手学习入口不恢复。

## 候选场景的表达边界

以下是可以优先验证的方向，最终以已实现且通过数据检查的规则为准：

- **开局死亡后的补枪结果**：显示开局时间窗、死亡事件及之后规定时间内是否发生对该击杀者的击杀。未发生补枪不能证明队友有补枪机会，也不能直接称为孤立、冒进或队友失误。
- **闪到队友**：显示闪光事件、致盲时间和附近回合片段。可以提示核对投掷时机及队友路线，不能宣称这次闪光导致死亡或输掉回合。
- **死亡前的持械状态**：只有足够接近死亡时刻的有效位置样本才可描述持刀或投掷物。必须显示采样限制；拿着道具死亡可能属于正常战术任务。
- **开局路线与交战节奏**：描述在指定地图、阵营和时间窗里的频率。路线集中不等于可预测性失误，首杀参与多也不等于永久的“突破手”身份。

每个候选应具备：适用场景、规则版本、实际次数与分母、缺失样本数量、原始回合与事件时刻。回放应保留事件前的上下文，并标出触发点；全图 2D 信息用于复盘，不代表当时玩家能看到所有敌人。

用户可以认可、排除或暂缓一个候选。没有发现候选是一种正常结果，不能为了填满页面而虚构问题。

## 行动与前后比较

一次只保留一个主要动作，例如“接下来同样的 T 方开局，出点前确认与队友的同步时机”。动作是用户选择的尝试，不是系统保证能提高胜率的处方。

比较要求：

1. 以比赛发生时间区分行动前后；新导入的历史 demo 不能被误算成练习后的结果。
2. 保持地图、阵营、来源等已选条件一致。条件、规则版本或样本覆盖改变时明确提示。
3. 比较相同定义的发生次数、适用机会和比例，同时列出场数、回合数与日期。零样本显示不可比较，少量样本只陈述变化。
4. 保留前后各自的回合证据，让用户复核变化来自什么场景。人员、对手、装备和战术会变化，不能宣称因果关系。
5. 评分和胜率只作背景，不能代替目标行为的变化。

[Leetify 的评分说明](https://leetify.com/blog/introducing-leetify-rating/)明确区分单场表现与技能改善，并指出对手水平会影响评分。[其历史可见性技术说明](https://leetify.com/blog/enemy-actually-spotted/)也说明雷达 spotted 事件不等于准确的首次看见时刻，造成伤害所需时间不等于纯反应时间。这是设计边界的参考，不是对当前 CS2 实现精度的保证。

## 0.3 暴露出的交互问题

首屏的十二张指标卡与五个统计页签，要求用户先阅读大量平台上已经熟悉的数据。热力图和证据位于后面，但缺少“为什么看这个回合”的解释。

筛选重新加载会卸载统计页签，使当前页签与趋势指标重置。热力图只有前五个区域按钮，图上其它格子不能选择；“区域 1”这样的编号也不是稳定的战术地点。证据直达事件时刻，缺少行动之前的过程。全局统计和单个地图分组并列时，范围容易混淆。

这些问题应通过明确当前复盘任务、保存浏览状态、统一样本范围和提供上下文来解决，不能只换颜色和卡片样式。

## 价值验证与验收

技术验收：每条观察能定位到正确比赛、回合和事件；过滤条件对观察、证据和比较一致；无匹配、少量样本、旧缓存、缺位置数据均有诚实状态；取消更换账号不清空原绑定；小窗口能操作且不靠页面横向溢出显示内容。

用户价值验证：观察目标用户能否在几分钟内找到一个愿意查看的回合，是否认可其中的问题，能否说出下一场的一个具体动作，以及导入后续比赛后是否回来复核。记录这些流程中的放弃点，比首页访问次数更接近真实价值。

盈利仍是待验证假设。先验证持续复盘与返回使用，再评估进阶工作流的付费意愿；不以未经验证的上分承诺、伪排名或数据焦虑推动付费。
