# 0.7.0：个人数据与进阶分析

这一版把已缓存的比赛事实组织成六个数据分区：总览、输出与突破、团队与道具、残局与经济、趋势、个人记录。地图、来源、T/CT 筛选同时作用于计数、分组和例子回合。复盘候选附有可跳转的回合；记录标签只在真实条件发生时出现。

## 数据范围

基础数据保留当前筛选中的全部比赛。标为“5v5 分析”的部分只采用已有缓存中符合标准 5v5 条件的比赛：竞技模式元数据，或经过人数、回合结构验证的第三方 5v5 比赛。双人、重生、超出 5v5 人数等比赛不混入这部分分析；界面显示采用的场数和回合数。

一局是否计入个人回合，取决于该玩家的回合经济快照。没有参与记录时，不因出现一条助攻或其他事件就补出一个零表现回合。相同 demo 校验和去重，其他账号排除。

“比赛胜率”和“回合胜率”分别计算：

- 比赛胜率 = 胜场 / 已知结果场数。已知结果包括胜、负、平；未知结果不进分母。结果采用缓存中的整场结果，选择 T/CT、经济分组或输赢回合不会重新判定整场胜负。
- 回合胜率 = 胜利回合 / 实际参与回合。同一场比赛可以同时出现在“获胜回合”和“失利回合”分组中，分组场数不能直接相加当成总场数。
- 所有均值和百分比先合并分子、分母再计算，不平均各场的百分比。分母为零或所需数据缺失时显示 `—`；真实零次、零伤害仍显示 `0`。

## 主要指标

| 数据             | 计算方式                                                                             |
| ---------------- | ------------------------------------------------------------------------------------ |
| ADR              | 敌方实际生命伤害 / 参与回合；过量伤害按目标剩余生命截断                              |
| 非道具 ADR       | 每回合 `max(0, 敌伤 − HE/燃烧伤害)` 的总和 / 参与回合                                |
| HS%              | 爆头击杀 / 敌方击杀，不是子弹爆头命中率                                              |
| K/D、(K+A)/D     | 敌方击杀、助攻与全部死亡的比值；死亡为零时不构造无限值                               |
| KAST             | 有击杀、助攻、存活或被补枪的回合 / 参与回合                                          |
| 首对枪参与、成功 | 本人的首杀或首死 / 参与回合；首杀 / 首杀与首死之和                                   |
| 首杀转胜         | 本人首杀且团队获胜的回合 / 本人首杀回合                                              |
| 补枪             | 队友被击杀后 5 秒内反杀该击杀者；本人补枪和本人死亡被队友补掉分开计数                |
| 未被补枪死亡回合 | 死亡且没有被补掉的回合 / 死亡回合；分母不是“可补枪机会”                              |
| 残局             | 记录的 1vN 尝试与胜利；保留 1v1、1v2 等分组                                          |
| 道具伤害效率     | 敌方 HE/燃烧伤害 / HE 与燃烧弹投掷数                                                 |
| 闪光效率         | 敌方致盲人次或总致盲秒数 / 闪光投掷数；人次要求单次致盲超过 1 秒，总秒数包含较短致盲 |
| 经济均值         | 装备价值、花费各自除以本项已知的回合数，不因为另一项缺失而丢弃有效数据               |

Rating 使用历史公开的 HLTV 1.0 公式；本地 RWS 采用既有的伤害与炸弹目标分配计算。两者的聚合只使用适用的标准回合，RWS 另排除无法定义的回合。基础击杀、伤害和死亡包含回合胜负确定后的追枪，首对枪与 RWS 的关键事件截至胜负确定时。

武器表分别展示击杀、爆头击杀、伤害和真实射击事件数。一次射击可能造成多条伤害记录；道具投掷也有独立计数，因此这里不把伤害事件除以射击数来生成命中率。

## 复盘候选与真实记录

候选用于选择值得回看的情境，不把相关性当作失误判决。每类最多提供三个真实回合例子；已知关键事件时从事件前约 4 秒开始，没有精确事件时从回合开始。

| 候选           | 触发条件与显示分母                                                  |
| -------------- | ------------------------------------------------------------------- |
| 首杀后未能转胜 | 至少 5 次首杀，其中至少 2 回合失利；失利次数 / 首杀回合             |
| 死亡未被补掉   | 至少 10 个死亡回合，其中至少一半未被补；未被补次数 / 死亡回合       |
| 队闪回合       | 至少 2 回合队友被闪超过 1 秒；队闪回合 / 总回合                     |
| 未投道具回合   | 至少 20 回合，零投掷至少 10 回合且占比至少 40%；零投掷回合 / 总回合 |
| 多杀亮点       | 至少 3 个多杀回合；多杀回合 / 总回合                                |
| 残局亮点       | 至少 3 次尝试且至少 2 次获胜；获胜 / 尝试                           |
| 闪助亮点       | 至少 2 个闪助回合；闪助回合 / 总回合                                |

趣味记录按回合计数，包括三杀、四杀、五杀、残局获胜、道具多杀、刀杀、300 敌伤、百伤零杀、双补枪、双闪助、AWP 三杀、低装备多杀、下包、拆包和 1v3 以上获胜。低装备要求已知装备价值不超过 2000 且至少两杀；缺失装备值不算低装备。同一回合可以获得不同标签，但三、四、五杀标签按精确击杀数互斥。没有人群排名或稀有度推断。

## 趋势和稳定性

上下半场必须从未做阵营筛选的原比赛中验证第 13 或第 16 回合换边；缺少早期回合、异常换队等情况标为未分类。加时单独分组。月份使用 UTC 的 `YYYY-MM`，不会随电脑时区变化。

至少四场有日期的标准比赛才展示两段比较：最近和此前两个等场数、不重叠的窗口，每段最多五场。两段覆盖的地图、来源、模式和版本一致时，才标为相同情境；指标变化仍是样本的描述。ADR 中位数和中间 50% 区间展示逐场分布，与按回合汇总的整体 ADR 是不同问题。

连胜、连败是当前已选比赛库中的样本连续结果，不代表未导入的全部历史比赛。平局、未知结果和非标准比赛会中断场次连胜；回合连胜不跨比赛，缺少中间回合也会中断。

## 缓存兼容与验证

进阶分析只读取现有逐场、逐回合缓存，在汇总时派生新字段。没有新增原始采样，没有升级 demo 缓存格式，也不要求重新解析。账号、原报告、录像和 demo 数据保持原位。统计 AI 只挑选有界、匿名的汇总事实；高级字段明确标记为标准 5v5 子集。

定向测试覆盖空库、混合模式、独立经济分母、未知比赛结果、T/CT 筛选、MR12/MR15 半场、UTC 月份、等窗口比较、连胜中断、候选证据和记录阈值，也验证助攻不会制造参与回合、射击数不会混入伤害事件或道具投掷。

另外用已有三场、55 回合的隔离 QA 缓存完成只读核对：加法指标满足全阵营 = T + CT，各高级分组保持回合与伤害总数，全部例子能定位到现存回合，读取前后缓存文件 SHA-256 完全一致。测试和 QA 没有启动游戏、解析器或云端 AI 请求。
