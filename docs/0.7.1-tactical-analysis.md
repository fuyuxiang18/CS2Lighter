# 0.7.1 战术诊断

## 从战术逻辑组织数据

本版提炼用户提供的战术手册中的通用决策框架：投入人员、装备、道具和时间，争取有用的空间，创造更有利的交战，通过协同交换把优势转成回合目标，再针对实际薄弱场景训练。

数据浏览围绕四个问题展开：

1. **优势兑现**：拿到首杀后是否存活，多久之后死亡，这些回合最终怎样结束？击杀之后继续争取什么目标，比单独看击杀数更有用。
2. **协同交换**：首死是否在五秒内被补，补枪和闪光助攻发生在哪些回合？复盘关注共同目标、启动时机和第二人的枪线。
3. **道具配合**：投掷之后有哪些可记录效果，队友是否受到影响？把投掷安排与接敌动作放在同一段复盘中检查。
4. **经济与目标**：个人装备条件下的输出、亲自下包后的结果，以及不同人数残局的处理。针对具体情境找动作，而不是只给一个总评分。

文档关于默认的三项判断依据——己方配置、对手习惯、即时信息——用于组织复盘提问。位置热力图仍表示位置分布；不把到达某处直接解释为获得图权。地图战术草稿、私人队伍配置、未核实的经济金额和训练生理解释不进入自动计算规则。

## 事实、复盘与训练

每个场景显示实际次数与条件分母、该组回合的胜率和 ADR，并提供最多六个真实回合入口。结论只描述观测到的模式，训练建议以可以在下一场执行的动作表达。

枪位判断保留为视角复盘问题：双方与共同掩体的距离、同时暴露的方向、己方交叉枪线、开枪或投掷后的位置暴露、击杀后的换位选择。现有缓存不能计算预瞄、急停、露身面积或信息优势分数，因此这些问题不生成数值评分。统计与训练建议放在同一流程，界面不重复铺设免责声明。

## 计算范围

- 使用当前账号以及地图、阵营、来源筛选后的标准 5v5 逐回合事实；先按 demo checksum 去重。
- 所有比例汇总分子、分母后计算，不平均各场百分比。没有符合条件的分母时显示空值。
- 首杀、首死沿用既有敌我首个击杀定义，不等于突破尝试。
- 首杀后十秒内死亡只纳入时间字段和 tickrate 有效的首杀回合；未死亡的有效首杀回合也计入分母。回合结算阶段的事件沿用原缓存口径。
- 首死被补沿用五秒补枪窗口；未被补是事件结果，不是已验证的补枪机会失败。
- 闪光致盲统计持续超过一秒的事件。未记录这类事件不等于一颗闪没有战术用途；闪光助攻也不转换成单颗闪成功率。
- 雷火场景按回合中的 HE/火焰投掷与已记录道具伤害划分，不把伤害强行归给某一颗投掷物。
- 低装备指个人已知装备价值不超过 2000，按是否造成敌方伤害分组；未知装备值不当作零。
- 个人下包只统计 T 方本人下包的回合，不代表全队所有守包回合。
- 1v1 与 1v2+ 分别统计所有对应尝试及成功率，回放同时涵盖赢与输。
- 回放事件时间无效时使用有效回合起点；无法定位的异常记录不制造虚假 tick。

## 数据与隐私

本版只增加汇总时的派生字段。demo 缓存仍为格式 3，不改变逐回合原始字段、不新增数据库迁移、不运行原始解析器。浏览和筛选不会调用云端 AI。原有账号、笔记、练习、AI 报告和录像存储保持兼容。

验证使用手算合成样本和现有缓存的只读核对；不克隆用户数据库或生成新的完整测试资料库。
