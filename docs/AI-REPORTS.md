# AI 统计复盘

本功能支持用户配置的 OpenAI 兼容 Chat Completions 服务，以及本机 Ollama 的 `/v1` 兼容接口。它不使用 ChatGPT/Codex 订阅额度；云端 API 的权限和计费由用户配置的服务决定。本项目不捆绑模型或 API 密钥。

本文说明个人及单场的**统计点评**。从 0.6 版起，已录制的单个对枪还可单独生成[视频点评](VIDEO-AI-REVIEW.md)。两者共用服务与模型配置，但使用不同输入、提示词和缓存；统计点评的去身份化范围和评分规则不能套用于视频点评。

## 发送范围与触发

- 进入页面、读取已缓存报告、保存配置均不调用模型。只有明确点击生成/重新生成，才执行最多一次请求；失败不自动重试。
- 个人报告使用当前地图、来源、阵营筛选下最近最多十场；单场报告只使用所选比赛及本人参赛回合。生成前展示场次、回合和可引用证据数。
- 发送合计数字指标、计算口径、地图/阵营/来源/模式/build 分组、阵营汇总、匿名武器统计、残局人数分组及抽样回合事实。个人报告每场最多四回合（总计最多 40），单场最多 24 回合。这不是随机样本，不能从这些回合推算总体频率；频率应使用合计指标。
- 昵称、SteamID、checksum、比赛确切日期、demo 文件路径、配置密钥和本地证据映射不进入模型 payload。比赛仅标为 `M1` 等、回合证据为 `r001` 等；非标准地图名转为 `custom-map`。聚合统计仍属于个人数据，选择云端时会发送到用户指定服务。
- 统计点评的 AI 输入只有统计事实，不含视频、截图、音频或位置轨迹。即使另行生成了 POV 片段，统计点评也不会上传它。视频点评另有“预览画面 → 发送画面并点评”流程，图片可能包含游戏昵称、头像或聊天。

## 内容与评分边界

报告固定包含摘要、玩法风格、观察、建议、五维评分和限制说明。中文风格标签必须是一个 2–5 字汉字短语，英文为 2–5 个单词，并另附简短解释与证据。摘要、风格、观察、每条建议和所有非空评分必须引用输入中存在的回合 ID。

五维固定按以下顺序展示，分数为模型主观的 0–100 整数，不是等级、百分位、平台分数或经过标定的能力值：

| 维度 | 允许使用的依据                                   | 不能据此断言                                                           |
| ---- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| 枪法 | 击杀与非道具伤害产出、爆头率、武器构成           | 看过预瞄、反应时间、连续压枪或鼠标操作；用低狙击枪爆头率直接认定枪法差 |
| 突破 | 首对枪参与、成功、首杀后回合转化，结合 T/CT      | 所有首杀都是攻点突破；首杀后输局都是本人决策问题                       |
| 补枪 | 自己的补枪击杀、自己死亡后被补，明确五秒事件窗口 | 未补枪就是当时有机会没补；把被队友补枪当成本人的补枪能力               |
| 道具 | 伤害、闪光效果、助攻、队闪及使用情况             | 投掷数量越多一定越好；零投掷就是记录缺失                               |
| 残局 | 残局尝试、获胜及 1vN 分布                        | 将少量 1v1 胜利当成稳定的 1v5 能力；无残局也虚构评分                   |

有对应统计数据的维度应给出整数分和依据；缺少对应情境的维度必须为 `null` 并显示“数据不足”，不以零分或 50 分占位。小样本仍可作暂定评价，但必须说明样本规模与不确定性。同组条件未控制出生位、角色、队友和对手强度，AI 只能提出待回放验证的建议。

返回 JSON 需通过字段、长度、数量、引用及评分范围检查；无害额外字段不参与展示，单个完整的 JSON Markdown 代码块可规范化读取。截断输出、虚构引用和不合法评分不会缓存，错误分别显示为输出截断、空内容、JSON 无法读取、结构/标签不符、引用不符或评分不符，不再只给出笼统的“校验失败”。

结构校验只能证明引用存在、输出格式合规，**不能证明模型文字的每项判断正确**。UI 因此同时展示“模型主观评估”“事实输入”、样本范围、限制及原始回放入口。

## 本地缓存与密钥

报告写入个人数据目录的 `ai-reports`，缓存键包含账号摘要哈希、事实与证据上下文哈希、服务类型、端点、模型和提示词版本。模型/筛选/事实变化不会错误复用旧报告。同一上下文同时点击只产生一个请求；重新生成显式覆盖该上下文的报告。密钥不进入缓存键、报告文件或日志。

0.6.1 使用统计提示词版本 2。旧报告文件保留；新版五维报告需主动生成，读取界面不会自动产生费用。新增输入来自已有 `demodata` 统计，不修改 demo 缓存版本，也不重解析原始文件。

Electron main 持有密钥；配置通过 OS safeStorage 加密后另存 `ai-config.json`，普通 settings 和 daemon 不接收密钥。renderer 只得到是否已配置密钥，不可读取明文。加密不可用（含 Linux `basic_text`）时拒绝保存密钥；无密钥的本机 Ollama 仍可使用。Windows DPAPI 保护不等于能防御已在同一 Windows 用户下运行的恶意程序。

服务端地址必须 HTTPS；仅回环地址可用 HTTP。Ollama 选项限定回环地址。拒绝 URL 内嵌用户名/密码、查询串和片段，禁止 HTTP 重定向。

0.6.2 可在“设置 → AI 点评”保存输出 token 上限，默认 240,000，支持 1–1,000,000 的整数；个人、单场和视频点评共用。旧配置缺少此字段时读取默认值，不改写加密密钥。调整上限不使已有点评失效，需要采用新上限时主动重新生成。

兼容服务将此数值传为 `max_tokens`，官方 `api.openai.com` 传为 `max_completion_tokens`。它是请求上限，不是要求输出长度，也不是固定消费量。模型或代理可能拒绝超出自身限制的值，此时需要调低设置；软件不静默降低上限或自动重试。思考模式仍遵从所选服务的默认行为；不把推理文本当作最终报告。

两类请求的响应体容量按 `max(2 MiB, token 上限 × 64 字节)` 限制；总等待时间按每 24,000 tokens 四分钟向上取整，最少四分钟、最多三十分钟。默认 240,000 对应 15,360,000 字节和三十分钟。最终报告 JSON 仍限制 32,000 字符，并继续校验字段长度、引用和评分；扩大生成预算不意味着要求长篇点评。模型/代理是否支持 JSON 模式和这些参数取决于其实现；本版不承诺所有兼容服务都可用。

依据：[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)、[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 验证范围

AI 单元测试使用合成事实与模拟 HTTP 响应验证：去身份化、场次数量限制、证据引用、五维评分与缺数据处理、短风格标签、默认及自定义 token 参数、旧配置兼容、设置持久化与非法输入拒绝、思考文本与最终结果分离、超时、响应大小、错误分类、无自动重试、缓存隔离、并发去重和不落盘密钥。模拟用例成功不代表真实模型输出成功，也不代表接入了用户的付费服务。开发验证不得外发用户数据或消费真实 API。
