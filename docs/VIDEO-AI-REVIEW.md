# 视频点评的输入与边界

视频点评针对用户当前选中的一段对枪。它与跨比赛数字点评使用不同提示词和缓存，不会在打开视频、切换页面或抽帧时调用模型。

它与[统计点评](AI-REPORTS.md)共用用户配置的服务、模型和操作系统加密密钥。两类点评都不使用 ChatGPT/Codex 订阅额度，也不捆绑模型。选择云端服务时，图片输入的权限和费用由该服务决定；配置的模型必须支持视觉输入和 JSON 输出。

## 实际流程

1. 用户生成真实 CS2 POV 视频，选择单个对枪事件，再点击本地预览。
2. 服务端只从受控且已完成的录像缓存抽帧，不接受渲染进程指定任意磁盘路径。己方和已录制的对手视角各最多六帧；有真实交火事件时优先取事件前后及首尾，缺失事件时均匀采样。采样截止该视角玩家死亡前，避免死亡后自动观战画面被误认为本人操作。
3. 界面展示实际将发送的 960×540 JPEG、帧 ID、录像秒数、demo tick 和完整回合事实 JSON。图片中的游戏昵称、头像和聊天可能仍然可见；这不是匿名化画面。不会单独附上 SteamID、本地路径、整段视频或声音。
4. 用户再次点击发送，才向设置中的服务地址和模型发起一次视觉请求。预览在本机内存保存十五分钟，并绑定目标服务和模型；改变目标需重新预览。没有自动重试，也没有静默丢弃图片后生成文字点评。
5. 返回内容必须引用真实帧 ID，并按“观察、推断、替代动作、不确定性”呈现，另给一至三个可执行练习及下一次可比场景的检查点。点评缓存独立保存在 `video-ai-reports`，不保存图片或 API key。再次本地预览可读取相同输入与模型的已存点评；重生成需要再次明确点击。

新录制批次按单个事件选择点评，使用该事件中实际完成的视角。已有单视角片段也可以预览并点评；没有录制的对手视角不会补编。旧片段若包含死亡后自动观战画面，抽帧仍依据该玩家的实际死亡 tick 截止，预览并不发送整段原片。

## 为什么只评一段

用户要知道的是某个选择是否合理、还有什么可行的替代动作。把很多回合混成一句“提高枪法”没有证据价值。批量录像可按事件逐个选择点评，每条建议能回到具体帧和对应视频时刻。单段表现不能推导长期打法、排名或能力分数。

对手视角属于事后信息。它可以解释为什么某个暴露角度危险，但不能证明本人当时知道对手的位置。demo 的观战 HUD 和雷达还可能提供实战本人看不到的信息，即使出现在本人镜头，也不能自动视作本人已知。系统校验引用对手帧的时间线条目必须标成事后视角；队伍语音、意图、视野外情况与声音都不能补编。回合数字是整回合总量，不能当作截取片段内发生的全部事实。

每视角六帧不是连续视频。不能据此评价毫秒反应、精确鼠标控制、急停时序、压枪时序、首次可见时刻，更不应给虚假枪法评分。模型对画面、遮挡、空间关系的理解仍可能错误；本地校验只能验证结构、引用与部分信息边界，不能验证散文判断真实。用户应回看片段确认建议。

视频点评不输出数值评分。统计点评中的有限主观维度分也不会作为这一段操作合理性的判定依据。

## 支持依据与限制

- OpenAI 官方文档说明，Chat Completions 可以用 `image_url` 内容接收 Base64 图片，一次请求可包含多张图片，图片会计入用量。视觉理解可能误读细小文字和复杂空间关系。因此本功能发送带明确时间标注的图片，保留手动证据复核，不宣传逐帧动作测量。[OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)
- Ollama 的视觉模型接收图片和文本，官方兼容接口也提供 `/v1/chat/completions` 的 `image_url` 示例。兼容接口只实现部分 OpenAI API，不代表每个模型都能看图。用户需要选择支持视觉与 JSON 输出的模型；应用不会仅凭模型名称猜测能力。[Ollama Vision](https://docs.ollama.com/capabilities/vision)、[Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)
- 不支持图片的服务器、拒绝该视觉请求的服务器，或明确表示看不到图片的模型，会得到可见失败提示。不会降级成统计点评。第三方服务若在内部无声丢弃图片，应用无法证明其真正使用了图片；有效 JSON 和真实引用 ID 也不是视觉事实正确性的保证。
- 视觉请求最多等待 180 秒，响应体上限 256 KiB。兼容服务使用 `max_tokens=4000`；官方 `api.openai.com` 使用 `max_completion_tokens=6000`。拒绝图片、JSON 模式或参数格式都可能导致失败，不能仅凭接口拒绝就断言模型没有视觉能力。地址限制与密钥保护沿用统计点评，不跟随 HTTP 重定向。
- 已有自动化测试使用合成模型响应验证一次请求、精确图片载荷、缓存、预览过期、目标变更、错误引用与边界拒绝；这些测试不代表真实云端或本地模型的建议质量。实际模型质量需要用户选择模型后，用有人工标注的录像进行另外评估。
