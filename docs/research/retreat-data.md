# R8：击杀后的掩体利用与撤回路线

核验日期：2026-10-22。以下区分实际观察、游戏资源和反事实移动计算，不把它们合并成同一种证据。

## 这次获得了什么

R8 新增一个可以利用现有真实数据验证的分支：**杀后离开原掩体并受击**。

1. 本人击杀敌人。
2. 从击杀后的下一 tick 起，连续完整帧表明本人对全部存活敌人的眼位参考枪线均被遮挡。
3. 本人随后在地面、同一高度移动，原本被挡的敌人枪线变成无遮挡；前后位置均来自 demo。
4. 此后发生来自新暴露敌人的实际枪械伤害。新枪线从离开掩体持续至受伤；不混入后来另一次击杀或另一场交火。
5. 在这段交火的每个 tick，用**当时的敌人眼位和环境状态**重新计算原掩体眼位。对全部存活敌人都仍被挡，才生成这一分支的证据。

这证明了“离开前后失去了哪条枪线的遮挡”，没有估算倒退速度，也没有宣称可以在受伤前走回去。建议围绕保留掩体、隔开新枪线后再接敌展开，不能把它改写为“肯定能够撤回”或“这就是死亡的唯一原因”。它同样不恢复玩家的意图、队伍报点或必须执行的战术目标。

实现位于 `src/node/death-review/cover-proof-provider.ts`，事实类型位于 `src/common/types/death-cover.ts`。没有把新事实写入原 `cover` 路线证书；旧的“可走的撤回路线与耗时”路径保留独立条件。

以下情况会阻止该分支：地图版本不符、动态物体或烟雾不明、敌人身份缺失、连续帧中断、原位置后来也被敌人打开枪线、本人没有位置移动、跳跃/下落/换高度、原位置已受到穿墙或道具等伤害、接敌与受伤同 tick 无法确认先后。致死帧已经是死亡状态时，不把前一帧的活人状态搬过去补证据。

## 地图和导航数据实际存在，为什么尚不等于撤回证明

在本机 Ancient 的 VPK 中只读查到：

| 资源                                   | 实际读取结果                                             | 可以提供的内容                               |
| -------------------------------------- | -------------------------------------------------------- | -------------------------------------------- |
| `maps/de_ancient.nav`                  | 371,064 字节；nav 版本 36；1,969 个区域                  | 导航多边形、连接、梯子、导航生成参数         |
| `maps/de_ancient/world_physics.vmdl_c` | 16,621,096 字节                                          | 静态世界的物理资源入口，可进一步解码碰撞形状 |
| nav 的 hull 0                          | 半径 16、高度 71、短高度 35.5、最大攀爬 16、最大斜坡 50° | 生成这个导航网格时的代理参数                 |

所以，“游戏不提供地图碰撞/导航资源”是不成立的。进一步读取这些资源有价值，可以生成候选路线并做人体体积的碰撞扫掠。但导航网格的连接并不直接证明某个时刻这名玩家能够沿该路线移动到终点。

[VRF 的 NavMeshArea 实现](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/20.0/ValveResourceFormat/NavMesh/NavMeshArea.cs) 明确区分文件中的基础属性与未保存到文件的运行时动态属性。[导航代理参数实现](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/20.0/ValveResourceFormat/NavMesh/NavMeshGenerationHullParams.cs) 还区分站立、蹲伏、可单向的落差连接等。因此不能将“图上连通”当作“反向也能走”或“比赛当时没有被挡”。

[VRF 20.0 的 PlayerMovement](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/20.0/Renderer/Renderer/Input/PlayerMovement.cs) 已经实现滑动、台阶、摩擦和加速，可以作为研究工具；它的行走控制器使用固定运动常数和站立/蹲伏体积，例如蹲伏高度 48、台阶高度 18。这些并不等于本次读取的 nav 生成参数，更不能证明与某一 demo 的服务器运行时状态完全一致。不能直接把查看器的移动演示接成确定性撤回判定。

## 真正的可撤回判定还要补哪些数据

| 缺口               | demo / 游戏资源能提供什么                            | 还需要完成的验证                                                                          |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 人体体积可通行     | demo 的碰撞 hull、蹲伏与运动状态；地图物理 hull/mesh | 按正确碰撞层和 mask 扫掠，覆盖 player clip、动态门、可破坏物及其他玩家                    |
| 脚下支撑与高度变化 | 位置、速度、ground 状态；物理地形；导航连接          | 处理斜坡、台阶、单向落差、移动平台和起始重叠；不能倒放历史坐标当作可行路线                |
| 反向移动耗时       | 起始速度、武器/姿态、部分服务器 cvar、逐 tick 轨迹   | 使用匹配版本的摩擦/加速/碰撞/子 tick 规则，并对实际轨迹做独立对照；不能用距离除以最大速度 |
| 路线当时仍有效     | 每 tick 的动态物体与玩家状态                         | 逐时刻验证路线；之前走过不等于现在还可以走                                                |
| 终点确实隔断枪线   | 对应版本的地图、动态环境与敌人眼位                   | 在相关时间窗持续重算，不能只检查出发时的一张图                                            |

现有 demo 的鼠标/键盘输入不是完整的服务器移动模拟状态。即使读取到导航文件，也不能跳过运动规则、物理碰撞和时间验证。后续可以做一个严格受限的地面平移模拟器，但必须先用真实已发生的运动验证误差和适用范围；目前没有给未验证模拟结果颁发 `verified` 路线证书。

## 本次实际复核与覆盖限制

- 新分支有 19 项边界测试：正例、原位置后来失去遮挡、其他敌人新增枪线、缺帧、缺敌人、动态/烟雾未知、同 tick 顺序、受伤后被迫离开、跨击杀关联、地面状态、取消等。正例使用明确可手算的合成几何，不伪称是真实对局命中。
- 对一份真实 Ancient demo 提取死亡前 449 tick：449 个主角帧、5 名敌人、1 次本人击杀，缺帧为 0。位置和事件链条具备，但这份 demo 是 patch 14173。
- 本机游戏现已是 patch 14191（`ClientVersion=2000934`，资源版本日期 2026-10-20）；现有已核验地图映射为 14190。本机 `demodata/visibility-maps` 和 `visibility-models` 均不存在，不能从中取回原版本几何。
- 因此本次真实样本没有生成 R8 正例，也没有用新地图去套旧比赛。没有原版本地图证据时，新分支同样保留未知。单次匿名汇总保存在工作区 QA 目录，未提交 demo、账号或对局原始数据。

另一个兼容性问题是：当前 `resolveVisibilityMap` 在检查旧缓存前先核对本机版本；将来即使有旧静态缓存也无法直接复用。改进应是按版本保留可认证的静态几何和动态模型资源包，再验证缓存内容；单独放开版本检查、混用旧静态地图与新动态模型会失去准确性。

本次同时修复了**已保存报告的读取**：即使原 demo 仍在、游戏资源已经更新，只要比赛修订、demo 校验和、玩家和死亡记录都相同，普通浏览和分析请求仍可读取原先保存的证据，并标明来源于已保存分析。这个读取不调用新地图或重新提取 demo，也不改写缓存对象；显式重新提取仍走当前资源验证，失败保留旧报告。没有比赛修订字段的旧缓存，仅在原 source/map 修订完全相同时沿用，避免跨版本错误关联。
