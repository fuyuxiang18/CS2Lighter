# 0.7.3 死亡操作风险与证据（替换版）

旧版 [50 类标签](0.7.2-death-review.md) 只作为历史事件与背景资料，不再统计为操作失误。新规则由本地确定性算法生成，不调用模型。界面优先展示一个改进点、最多两个独立次要风险，每项提供证据值、时间定位与建议。未知与无风险分开。

| 编号 | 名称         | 判断所需的实际证据                                                                                         | 对应改进                       |
| ---- | ------------ | ---------------------------------------------------------------------------------------------------------- | ------------------------------ |
| R1   | 首枪未急停   | 首枪的武器/模式精度基线、实际精度及可独立归因的移动损失；排除落地、转向等混杂                              | 在当前武器精度恢复后开枪       |
| R2   | 落地开枪过早 | 完整落地过程、射击时间区间、可独立归因的落地精度损失                                                       | 调整落地与开枪的先后           |
| R3   | 续枪过早     | 同一武器前次开枪、暂停后再次开枪、实测恢复轨迹及尚未恢复的精度                                             | 按这把枪的恢复情况延长停火间隔 |
| R4   | 压枪失误     | 确认同一目标、完整身体角域与射击时钟；起始发覆盖目标后，连续至少三发越过上下边界或至少三次越过左右边界反向 | 对照目标相对轨迹修正连续射击   |
| R5   | 多线暴露     | 同时三人及以上枪线，或两人夹角至少 30°；同一敌人集合连续至少 0.2 秒                                        | 用掩体隔开枪线                 |
| R6   | 身位控制过大 | R5 窗口内本人移动增加枪线；用当前敌人位置与前一帧本人眼位重新计算仍被遮挡                                  | 停在已验证暴露更少的位置       |
| R7   | 死磕一条枪线 | 真实交火→遮断枪线→本人重新拉出；双方位置仍在原角附近，对手已就绪，期间没有已知友方支援或道具改变局势       | 改时间、角度或与队友共同接敌   |
| R8   | 杀后暴露     | 击杀后持续枪线与后续枪械受伤，且存在当时可走、耗时足够的已验证撤回路线                                     | 沿证据中可用路线回到掩体       |
| R9   | 掏枪过晚     | 前后帧确认手持刀/道具/C4或已验证部署锁定，主动进入枪线，并在未准备好期间受枪械伤害                         | 越过拐角前准备武器             |
| R10  | 换弹时机错误 | 暴露时主动开始换弹，或换弹中主动拉出；实际枪械伤害发生在相同换弹与枪线窗口                                 | 回到掩体再换弹                 |
| R11  | 子弹管理有误 | 拉出之前已确认空仓、未在换弹；同一把枪主动接敌后受枪械伤害                                                 | 接敌前检查弹匣或提前切副武器   |
| R12  | 致盲强行对枪 | 自己的闪光仍在作用时主动新增枪线，期间受到该方向枪械伤害                                                   | 调整投闪与出掩体的顺序         |
| R13  | 致盲强行对枪 | 他人闪光作用时主动新增枪线，期间受到该方向枪械伤害                                                         | 先留在已验证遮挡处等待恢复     |
| R14  | 脱节交火     | 已见证原共同枪线，随后本人主动拉出并发生枪械交火；该交火窗口内所有活队友的实际支援枪线均被遮挡             | 对照脱节前后的位置同步推进     |

R5 的时长和夹角、R7 原角附近的位置范围以及 R4 的连续偏离次数属于复盘筛选口径。精度规则不套固定移动速度、通用连射发数或统一距离阈值；使用对应版本武器/模式资料和射击事件测量。精度损失同时投影到该次交火距离展示，不计算伪造的命中概率。

R14 按用户确认的实际队形变化口径，不推断“队友从任何路线都绝对来不及”。R12/R13 同名且重叠时合并展示，保留两条规则来源。

### 当前实际数据覆盖

- 当前核验过的官方武器资料为 patch 14190 的 `weapons.vdata`，按武器和模式区分。
- 本轮真实 demo 中部分 FireBullets 没有分别传输移动/空中精度分量。不能仅用接收事件那一帧的速度倒推出开枪瞬间是否急停；R1–R3 未能分离归因时只展示逐发测量与具体缺口。
- 本版尚未取得可认证的完整动画身体包络与目标射击时钟。实际 FBI 角色的静态网格已经超出其 view/hull bounds，因此不能把碰撞盒冒充全部身体；生产数据无法满足 R4 时不下结论。规则引擎的已验证输入测试不等于已具备真实目标包络。
- 眼位线段 trace 也不能认证人体移动路线、惯性、台阶和动态角色碰撞，生产提取尚不能提供 R8 的撤回路线证书。因此即使出现“击杀后死亡”也不会硬判 R8。
- 缺帧、地图版本不匹配、动态遮挡或身份不明都保留未知；不会为了凑满十四条而构造证据。
- 同一 tick 内动作顺序无法核实时只保留事件与测量，不将死亡前一帧的存活、换弹或武器状态搬到死亡帧。

## 枪线的含义

按用户选定的口径，检查的是眼位参考点之间的三维环境通路；另列敌人朝向与主角方位的角差。它不依赖屏幕比例或相机 FOV，也不将敌人背对主角改写为“没有枪线”。这不是伤害、穿透或实际屏幕像素可见性计算。

静态场景来自本机安装的地图与完整资源依赖。门、可破坏物和可移动道具按该 tick 的状态处理；动态模型不能确定范围时，不把相关未知区域当成无遮挡。烟雾没有可靠解码体积时保留未知结果。几何使用保守遮挡，玻璃等表面也可能阻断判定。

地图版本采用明确验证过的 demo patch 与安装版本对应关系，并记录本地 VPK 指纹。当前映射为 patch 14190、ClientVersion 2000930、Steam build 25815307；没有声称从 demo 中恢复了地图内容哈希。版本不匹配时不套用当前地图给旧比赛下结论。

窗口按实际连续 tick 合并，缺 tick 会断开窗口；完全包含在同一更大敌人集合窗口中的重复子窗口只显示一次。持续更长、超出多人窗口的双人交叉枪线仍保留。

## 逐发轨迹的含义

方向来自 demo 中 FireBullets 的实际射击中心角度，已经包含引擎生成该事件时的后坐力影响，不重复叠加 aim punch，也不把它画成随机散布后的真实弹着点。

先以完整实体句柄和生命周期核对射手，再与数据库射击事件唯一匹配。连射要求同一回合、同一武器、严格递增的 tick、连续的后坐力序列，相邻发间隔不超过 0.25 秒。单步垂直变化超过 15°或水平变化超过 30°时，不对该段套用缓慢上扬或横摆规律。换枪、重置和间隔会分段，不跨段连线。

这些观察折叠在原始方向资料中，不作为 R4 的替代判定，也不额外生成笼统练习建议。

## 数据和运行边界

- 原有逐场统计缓存格式仍为 3；基础死亡缓存不变，不升级 PostgreSQL schema。
- 每次只提取死亡前最多 7 秒，且不早于所在回合开始。原始 demo 只读，解析器为了还原实体状态会顺序读到窗口结束，然后停止。
- 单个后台证据任务串行运行。取消会结束子进程；任务失败可重试，完成结果可手动重新提取。普通打开只读取有效缓存。
- 原 demo 后来被移走或删除时，只要比赛修订未变，仍可查看已保存的证据；重新提取需要恢复原文件。删除比赛会同时清理该比赛的三类派生缓存，并阻止旧任务在删除后写回。
- 高频原始帧只在当前分析任务内使用，不写入数据库或保存整场快照。每个 demo 的进阶结果位于 `demodata/death-evidence/<checksum>.json.gz`，上限为压缩 8 MiB、解压 64 MiB，并验证内容完整性。用于规则重算的窗口事实单独压缩嵌入，单次解压上限 16 MiB，不传给前端；列表解码缓存有 32 MiB 容量上限。
- 规则版本独立于事实缓存版本。同版本结果直接读；规则变动从有效事实重算。旧记录没有新事实时显示“未分析”，只允许按需补提，不使整库统计或原轨迹失效。
- 地图缓存位于 `demodata/visibility-maps`，模型元数据位于 `demodata/visibility-models`，同一资源复用；临时地图导出在完成或取消后清理。
- 基础事件、射手身份、原始方向和环境遮挡分别核对。某类证据缺失不应抹去同一次死亡中其他已验证的数据。

## 依赖与复核

射击与实体提取使用固定版本 [demoinfocs](https://github.com/markus-wa/demoinfocs-golang/tree/8e1342e6585c)，地图资源读取使用 [ValveResourceFormat 20.0](https://github.com/ValveResourceFormat/ValveResourceFormat/tree/20.0)。工具在构建安装包时准备，用户无需安装 Go 或 .NET SDK。第三方许可证随安装包保留。

真实 demo 验证和合成边界测试分开进行：真实样本核对事件、资源与性能；合成测试覆盖遮挡、缺帧、旋转门、不同敌人集合、缓存损坏和取消等可明确手算的边界。QA 不复制用户数据库，不把 demo 或身份信息提交到仓库。
