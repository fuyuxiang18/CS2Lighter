# v0.7.2：逐次死亡复盘规则指南

死亡复盘使用本地事件规则，不调用 AI。当前目录共 **66 项：50 项可自动匹配，16 项等待额外数据**。自动匹配项包含动作、状态、交火结果和回合背景；匹配数量不等于失误数量。页面让用户从具体死亡回到证据和录像，再选择训练动作。

规则定义和筛选参数：`src/common/death-review/death-rules.ts`。判定实现：`src/node/death-review/build-death-review.ts`。本文中的秒数、速度和距离阈值都是本软件的筛选参数，不是武器精度常量。

“有复盘重点”表示值得点开录像确认，包含高速首枪、高速末枪、致盲期间开火等动作，也包含未交换、射击未造成枪伤等场景。这个标记不是判错或扣分；基础爆头、空中状态等事实单独保留。

## 数据与共同边界

- **K**：击杀事件，含双方坐标、空中状态、致盲、检视武器、穿烟和穿透标记。
- **D**：伤害事件。实际伤害用 `min(health_damage, victim_health)` 截断，最低为 0；不把溢出伤害累加。
- **S**：开枪/投掷事件，含武器实例、枪口事件时速度和 yaw。必须完整导入，数据库开枪行数与解析器 `shot_count` 相符。枪械使用显式白名单，刀、道具、C4、电击枪和未知武器不当作枪械开火。
- **B**：致盲事件，含来源、对象和记录时长。时长包含渐退过程；不能从时长判断屏幕是否完全变白。
- **P**：死亡前的真实存活状态快照，最多早 **0.25 秒**，同 tick 时还要求 `frame ≤ death.frame`。不调用会补帧的 2D 位置接口，不用死后掉落库存，不把位置推成视线。
- **R**：回合起止、胜方及按回合去重的 5v5 名单。**O**：下包、拆包开始等目标事件。

自动战术规则只对正式回合内的人类对敌死亡启用：回合需有完整 5v5 名单、没有复活/同一玩家重复死亡或机器人接管；模式需允许常规回合分析。完美比赛即使底层标成 casual，只要满足这些条件也可使用。自杀、队伤、世界伤害、热身、回合结束后死亡仍保留记录。缺少回合或有效 tickrate 的死亡保留基本信息，禁用时间判断与录像请求。

表中每条事实只需要一次满足条件的事件；涉及序列、人数或库存的最低证据另外列出。数据缺失时不计作“未触发”。所有前因窗口都截在本回合正式开始和死亡时刻之间；**补枪结果**是唯一明确读取死亡之后 5 秒的规则组。时间线按 tick、frame 排序，同帧不捏造 sub-tick 先后。

页面中的次数分母是已读取的死亡，不是全部对枪机会。不能据此说某动作使死亡率增加，也不能因为只出现一次就给玩家贴永久风格标签。训练列是供录像验证后选择的练习，不是自动认定动作错误。

| `simultaneous_visible_enemies` 同时看见多个敌人        | 同时刻本人眼睛、视角/FOV、敌方可见 hitbox、地图网格、动态遮挡、烟与闪；至少 2 敌满足完整可见条件 | spotted mask、多个伤害来源和几何连线都不等于实际看见；先在第一视角暂停，标可见敌人 |
| `multiple_visible_angles` 同时暴露多个有效枪线         | 同时刻多名敌人对本人有视线，结合各自朝向、闪光和武器状态                                         | 被多个敌人先后命中不等于同时可开火；回看对手视角，逐个确认威胁                     |
| `wide_peek_exposure` 拉出后新增过多暴露面              | 连续移动轨迹与逐帧可见性，明确拉出前后新增枪线                                                   | 地图 XY 距离不能代表宽拉；对照窄拉与原路线，看新增威胁发生在哪里                   |
| `repeek_same_angle` 受伤后重新暴露同一枪线             | 受伤、可靠中断视线、之后再次进入同一有效交战射线的时序                                           | 返回同一格子不等于重复 peek；练受伤后的换线或同步反打                              |
| `cover_distance_disadvantage` 共同掩体下的近远关系不利 | 双方眼睛、命中盒、同一遮挡边界与准确地图几何                                                     | 不能简单用“谁离任意墙更近”判近大远小；在同一角对照双方视角                         |
| `crosshair_placement` 接触时预瞄偏差                   | 首个真实可见目标时刻、本人完整视角、目标 hitbox、视野/遮挡                                       | 对着不可见敌人的上帝视角坐标不是预瞄目标；先标本人合理预期的出现点                 |
| `first_shot_inaccuracy` 首枪实际不准确                 | 对应游戏版本的武器状态、精度模型及开火数据，必要时实际弹道/随机种子验证                          | 高速不等于本枪真实散布；不硬编码未经验证的速度比例或恢复时间                       |
| `counter_strafe_timing` 急停输入与开枪时机             | 有覆盖的真实输入、速度序列、武器可开火/精度状态和 sub-tick 时序                                  | 只看开火瞬间速度不能反推按键方向和急停失败；录像与训练地图对照                     |
| `recoil_compensation` 后坐力补偿轨迹                   | 可靠原始输入、实际 recoil/aim-punch 存在性、游戏版本武器模型                                     | 默认 0、view-punch、换目标、观战采样不得当成压枪；先限定单武器连续交火段           |
| `mouse_oscillation` 非目标切换的输入振荡               | 连续真实 mouse delta/usercmd，已校验覆盖、采样间隔和服务器角度修正                               | 眼睛角度受后坐力与观战采样影响，不等于鼠标抖动；录像辅助区分转目标                 |
| `reload_exposure` 换弹期间遭遇有效威胁                 | 装填起止/取消状态、弹药、武器状态，结合真正威胁时刻                                              | 暂时没开枪不证明正在换弹；练确认安全后装填                                         |
| `empty_magazine` 弹匣耗尽后的交战                      | 正确武器实例的实时弹匣数与开火/装填状态                                                          | 射击事件数量不能倒推弹量，可能捡枪或换枪；结合录像练弹药检查                       |
| `weapon_switch_lockout` 切枪未就绪                     | 武器切换时刻、next attack/部署状态及当时威胁                                                     | 仅手持道具与之后阵亡不能推出武器无法开火；练出掩体前完成切枪                       |
| `missed_trade_opportunity` 存在机会但没有补枪          | 队友对目标真实可见、有可开火状态、合理目标信息和时间窗口                                         | 最近队友、距离近或未被补枪都不足以责怪队友；逐个看真实机会                         |
| `incorrect_information_read` 对已有信息的判断错误      | 仅重建本人已见/已听/已收到的有效信息；语音、雷达来源和时间需要明确                               | 不能凭上帝视角知道敌人在哪就判本人选择错；回放时先写当时知道什么                   |
| `unnecessary_rotation` 不合理转点/回防选择             | 本人当时信息集、目标状态、时间、可走路线、团队分工                                               | 对手最终出现位置不是当时可得信息；比较在原信息下的两个可行选择                     |

## 实现及资料依据

- 本仓库 `kills`、`damages`、`shots`、`player_blinds`、`player_positions` 等数据库表决定当前能保存什么；显示能力以这些实际字段为准。
- [cs-demo-analyzer 官方仓库](https://github.com/akiver/cs-demo-analyzer)：现有解析器及事件导出实现。声明可解析不代表历史缓存已保存全部字段。
- [demoparser 官方字段目录](https://github.com/LaihoE/demoparser)：列出了速度、武器状态、视角及部分 usercmd 字段，可供以后定向采集评估；必须另行检查具体 demo 的字段覆盖。
- [Awpy 官方可见性示例](https://awpy.readthedocs.io/en/latest/examples/visibility.html)：三角网格视线判断与烟、闪光、道具/物件等额外可见性条件。单纯线段不相交只说明几何连线可通。

本版不会为补齐上述 16 项而强制重解析全部旧 demo。死亡复盘缓存与已有比赛/习惯缓存分开管理；旧统计继续可读，有可用事件数据时再生成对应的死亡复盘结果。
